[devenv 2.3](https://github.com/cachix/devenv/releases/tag/v2.3) ships:

- **[Localhost URLs for processes](#localhost-urls-for-processes):** give every process with a declared port a `.localhost` hostname, opt in to HTTPS with the project's mkcert authority, and grant Linux capabilities without running services as root.
- **[A new dotenv engine](#a-new-dotenv-engine):** quotes, multiline values, variable substitution, ordered files, and hot reloads, parsed by the devenv CLI instead of Nix.
- **[Pin many package versions at once](#pin-many-package-versions-at-once):** `multiverse.pins` resolves a whole set of versions through the fewest nixpkgs revisions.
- **[A TUI you can configure](#a-tui-you-can-configure):** a personal settings file for viewport, statusline, colors, and keybindings, plus fullscreen log search and vim style navigation.
- **[Processes that stop when they should](#processes-that-stop-when-they-should):** configurable shutdown signals, cleanup after crashes, and `devenv tasks run` tearing down the processes it started.
- **[Smaller, faster, more observable](#smaller-faster-more-observable):** a 29% smaller closure, Nix 2.35, batched garbage collection, and process lifecycle events in trace output.
- **[Skills for Claude Code](#skills-for-claude-code):** declare on-demand knowledge, a primary agent, and per-agent effort from `devenv.nix`.

## Localhost URLs for processes

Remembering which port each service landed on gets old fast. devenv 2.3 adds a shared localhost proxy that gives every process with a declared port a stable hostname ([devenv#3141](https://github.com/cachix/devenv/pull/3141)):

```nix title="devenv.nix"
{ config, ... }:

{
  process.proxy.enable = true;

  processes.web = {
    exec = "python -m http.server $PORT";
    ports.http.allocate = 8000;
    env.PORT = builtins.toString config.processes.web.ports.http.value;
  };
}
```

`devenv up` now shows `http://web.<project-name>.localhost` next to the process, and the URL survives port reallocation. Override the hostname per process or per port when a service expects a particular name:

```nix title="devenv.nix"
{
  processes.web = {
    proxy.hostname = "app.localhost";
    ports.admin.proxy.hostname = "control.localhost";
  };
}
```

The proxy is opt in and disabled by default. On Linux the port 80 listener needs a one time `sudo` authentication; a privileged broker then stays alive for the lifetime of the manager, so detached processes and restarts never prompt again.

### HTTPS with the project's certificate authority

Enable HTTPS for an individual process and devenv issues a certificate from the mkcert authority the project already uses:

```nix title="devenv.nix"
{
  process.proxy.enable = true;
  processes.web.proxy.https.enable = true;
}
```

The proxy serves HTTPS on port 443 and keeps HTTP on port 80. Your process keeps speaking plain HTTP and receives `X-Forwarded-Proto: https`. Each project keeps its own certificates, and the shared proxy picks the right one per hostname.

### Linux capabilities

Some services need a kernel capability rather than a proxy, for example a server that binds port 443 itself. The native process manager can now grant a limited capability set while the service keeps running as your user ([devenv#3151](https://github.com/cachix/devenv/pull/3151)):

```nix title="devenv.nix"
{
  processes.web = {
    exec = "caddy run";
    linux.capabilities = [ "net_bind_service" ];
  };
}
```

devenv shows the requested capabilities, authenticates with `sudo` once, and the broker launches only the capability bearing processes declared in the evaluated configuration.

## A new dotenv engine

The `.env` integration used to be a Nix parser that copied the file into the store and understood only the simplest syntax. 2.3 replaces it with [dotenv-ng](https://github.com/cachix/dotenv-ng), invoked by the devenv CLI during evaluation:

- Single and double quotes, multiline values, comments, and `export` prefixes.
- Optional variable substitution across files.
- Ordered loading of several files, including files in subdirectories.
- Files generated by tasks, and hot reloads when a file changes.

Values still land in `config.env`, explicit `env` definitions still take precedence, and the evaluation cache tracks every file and substitution so edits apply on the next command. This closes seven long standing issues, the oldest open since 2023 ([devenv#775](https://github.com/cachix/devenv/issues/775), [devenv#1208](https://github.com/cachix/devenv/issues/1208), [devenv#1333](https://github.com/cachix/devenv/issues/1333), [devenv#1591](https://github.com/cachix/devenv/issues/1591), [devenv#1652](https://github.com/cachix/devenv/issues/1652), [devenv#1994](https://github.com/cachix/devenv/issues/1994), [devenv#2176](https://github.com/cachix/devenv/issues/2176)).

Older CLIs that resolve newer modules fall back to the legacy parser instead of failing, so mixed version teams keep working.

The [SecretSpec](https://secretspec.dev) integration remains the recommendation for secrets. The bundled SecretSpec is now 0.20.

## Pin many package versions at once

devenv 2.2 introduced [nixpkgs-multiverse](https://github.com/fzakaria/nixpkgs-multiverse) pins such as `multiverse.cmake."3.16.5"`. Each pin resolved on its own, so five pins could mean five nixpkgs revisions to fetch and evaluate. `multiverse.pins` resolves the whole set through the fewest revisions that can serve every requested version:

```nix title="devenv.nix"
{ multiverse, ... }:

{
  packages = multiverse.pins {
    cmake = "3.26.4";
    bun = "0.7.0";
  };
}
```

You get exactly those versions, and Farid Zakaria's [write up](https://fzakaria.com/2026/08/17/nixpkgs-multiverse-the-fewest-nixpkgs) explains why the selection is minimal. See [pinning](/pinning/#pinning-an-individual-package-version) for details.

## A TUI you can configure

The TUI now reads a personal, versioned settings file from `~/.config/devenv/config.yaml`. It covers presentation and interaction only, so the reproducible project configuration stays in `devenv.nix` and `devenv.yaml` ([devenv#3117](https://github.com/cachix/devenv/pull/3117)):

```yaml title="~/.config/devenv/config.yaml"
# yaml-language-server: $schema=https://devenv.sh/devenv.user.schema.json

version: 1
tui:
  viewport: top
  statusline:
    position: bottom
    layouts:
      main:
        left: [profiles, summary]
        center: [project]
        right: [elapsed, key_hints]
  keybindings:
    logs:
      top: [home, "g g"]
      bottom: [end, "shift+g"]
  behavior:
    follow_logs: true
    log_history_lines: 10000
```

`devenv user-config validate` checks the file, including key conflicts and statusline formats, and the published JSON Schema gives you editor completion. See [TUI customization](/tui-customization/) for every option.

The log viewer gained fullscreen search with highlighted matches, vim style scrolling, and a copied line counter. Process search stays visible in narrow terminals, and the activity tree draws connected branches so nested builds read at a glance.

Two smaller shell quality of life changes: the `(devenv)` prompt prefix can be turned off with `prompt_prefix: false` in `devenv.yaml` or globally in the user configuration, and the reload shortcuts no longer intercept Ctrl-Alt input from full screen applications such as Neovim ([devenv#3107](https://github.com/cachix/devenv/issues/3107)).

## Processes that stop when they should

Every process now has a configurable stop signal and grace period, applied to restarts as well:

```nix title="devenv.nix"
{
  processes.postgres = {
    exec = "postgres -D $PGDATA";
    shutdown = {
      signal = 2;   # SIGINT: fast shutdown
      grace = 10;
    };
  };
}
```

The built in PostgreSQL service already uses SIGINT, so `devenv down` no longer waits on a slow smart shutdown.

The rest of this section is about orphans. A task that depended on a process, such as `after = [ "devenv:processes:postgres@ready" ]`, used to start it and never stop it, leaving PostgreSQL holding its port and data directory after `devenv tasks run` returned. Tasks now tear down the processes they started, in both TUI and non TUI mode.

The same cleanup applies when things go wrong. If `devenv-tasks` or the native manager crashes, a guardian cleans the abandoned service session and the next manager reconciles it before starting the same process again. Stop and restart clean the entire session, including descendants in separate process groups. A second Ctrl+C exits immediately and still kills the processes it was waiting on. Logging out no longer loses a detached manager: devenv keeps a copy of its state in `.devenv`, so `devenv processes down` works after you log back in.

External managers got a proper contract. Detached mode is supported by process-compose, Honcho, Hivemind, and Overmind, unsupported operations fail before launch, and process-compose owns restart and readiness so short lived processes exit cleanly ([devenv#2879](https://github.com/cachix/devenv/issues/2879)). `devenv down` gracefully stops Overmind and waits for it to exit, and a foreground `devenv up` with an external manager is visible to other terminals.

## Smaller, faster, more observable

**Smaller closure.** The devenv closure shrank from 528 MB to 376 MB. `cachix` and `nixd` were built against different package sets than devenv itself, pulling in duplicate copies of glibc, OpenSSL, curl, Boost, ICU, and the Nix libraries. Everything now ships once.

**Nix 2.35.** The bundled Nix moved from 2.34.8 to 2.35.2. When the daemon is also 2.35 or newer, `devenv gc` deletes old environments in a single batch with visible progress, which is dramatically faster on stores with many generations.

**Faster shells.** Git hook installation is skipped when the installed hooks already match, and file watching uses far fewer allocations for large dependency sets while continuing to track files created later or replaced atomically. GC roots survive moving a project directory, and existing root symlinks are updated atomically.

**Process lifecycle in traces.** `--trace-to json` output now carries structured `ports` and `ready_probe` fields per process, and exits and supervisor restarts are exported as `exited` and `restarted` events instead of free form log lines. OTLP destinations also export Nix evaluator heap and garbage collection metrics for diagnosing memory use. Trace sinks serialize events lazily, so enabling tracing costs 89% fewer allocations than before, and JSON export throughput went up 2.6×.

**Better errors.** Module errors point at the `devenv.nix` or imported module that defined the offending option instead of `<unknown-file>`. `devenv tasks list` prints a readable tree with inline descriptions, and `devenv hook <shell> -- --no-tui` forwards arguments to the auto activated shell in Bash, Zsh, Fish, and Nushell ([devenv#3128](https://github.com/cachix/devenv/issues/3128)).

**Test harness.** `devenv-run-tests` reports the runtime and shell closure size of every test and fails a test whose closure exceeds `max_closure_size` in its `.test-config.yml`. We use it to keep the language examples honest.

## Skills for Claude Code

The [Claude Code integration](/integrations/claude-code/) can now generate skills, the on demand knowledge folders Claude loads when a task matches their description:

```nix title="devenv.nix"
{
  claude.code.skills.database-migrations = {
    description = "How to write and run migrations in this project.";
    allowedTools = [ "Read" "Grep" "Bash" ];
    resources."references/schema.md" = ./docs/schema.md;
    content = ''
      Migrations live in `migrations/` and are applied with `diesel migration run`.
      One logical change per migration; never edit an applied migration.
    '';
  };
}
```

Skills support model and effort overrides, forked subagent contexts, and bundled resource files. Agents gained an `effort` setting, and `claude.code.agent` selects the primary agent for the main conversation. `devenv info` reports both.

See the full [changelog](https://github.com/cachix/devenv/blob/main/CHANGELOG.md) for the rest, including fixes for concurrent `devenv shell` entries into a fresh project, `devenv --from` leaking the current directory's `devenv.local.nix`, and a WSL2 crash on `0x0` terminal sizes.
